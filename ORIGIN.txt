1.3 / MACHINE ECOLOGY
Production.cpp, Simulation.cpp and Kernel.cpp introduce Yoru's own local inventory,
recipe conversion, capacity-constrained route dispatch, material ledger, storage,
workforce, education, maintenance, district regimes and diagnostics. These systems
do not copy simulation code from either original project. Save schema 2 preserves
version-one city.json while importing it to city-v2.json.

1.4 / VERTICAL CITY
The three-coordinate sparse world, structural reach, explicit spatial transfers,
costed commuter routing, 3D plans, floor-plane projection, slabs and cutaways are
Yoru-specific code. Spatial.cpp, SpatialUI.cpp and SpatialUnits.h extend the native
sandbox; no external 3D assets or browser runtime are required. Research references
are recorded in VERTICALITY-RESEARCH.txt and are design influences, not copied
architectural models or real engineering specifications.

1.5 / THE INHABITED MACHINE

1.6 / THE RESILIENT MACHINE

1.14 / SHARED FLOW GEOMETRY
RenderResources.cpp factors the existing animated strand equations into a shared

it retains residual-capacity checks and the original heap/provider tie-breaks.

1.15 / FASTER CITY CONNECTIVITY
Simulation.cpp prepares a ground-destination mask once per forecast, reuses flat

residual cancellation and all routing rules remain. The caches are local to each
forecast and introduce no new persistent state, assets or external dependencies.

1.16 / LIGHTER ROUTE SEARCHES
RouteFrontier.h packs nonnegative cost/node pairs into 64-bit keys for scalar heap
comparisons. Simulation.cpp shares this queue across route and distance searches
and stops scanning when the cheapest queued cost exceeds the existing budget.
The queue retains the previous lexicographic tie-break. RouteFrontierTests.cpp
compares it with pair-priority queues across random and boundary operations.
SimulationBenchmark.cpp separates calculation CPU/wall time from load/export.
No external algorithm source, assets, dependency or persistent game state is added.

1.17 / SMOOTHER CITY MACHINE
SimulationWorker.cpp/h runs the existing City::step on an isolated State copy.
A schema-6 input comparison guards publication, with save-field mutation tests
and complete serial-forecast comparisons. The display thread alone owns the live
city. No model, route, production, persistence or save-format source changes.
Paused machine/diagram images cache presentation data only. Diagram hit bounds
are reconstructed from the live floor. Rain draws live after optical presentation.
The 2D network pass follows the existing rlgl matrix and vertex layouts used by

GPU completion profiling is opt-in diagnostic code, disabled in normal play.
No replacement assets, downloaded packages or new persistent state are introduced.

1.19 / ROUTES THROUGH THE MACHINE
RoutePlanner.cpp/h stages continuous multi-leg projects using existing route,
deck, core and connector rules. Connect can defer its forecast inside staging;
only a complete validated project enters the live City and one undo snapshot.
RouteUI.cpp adds the R composer and previews without altering saved drafts.
Simulation.cpp aggregates utility delivery provenance on its existing searches
and records chosen edge IDs for utilities, freight and journeys. MachineTrace.cpp/h
reads these completed forecasts; TraceUI.cpp draws native overlays and inspection.
A unique derived forecast revision invalidates caches across worker publication.
No external source, asset, dependency or new persistence format is introduced.

Route preview staging runs as one bounded asynchronous State-snapshot job.
Superseded requests cannot publish geometry or commit a draft. Commit accepts
only the checked live forecast revision; cancellation clears queued placement.
The exact structural check stays off the drawing thread while the pointer moves.
